# Совместимость текстового поиска

Эталон фильтра MATCH — SQLite FTS5 3.54.0 с `unicode61`. Точные source_id и
параметры сборки находятся в `testdata/fts5/manifest.json`. Генератор проверяет
весь манифест и отказывается молча использовать другую сборку.

Проверка установленного CLI:

```sh
python3 tools/fts5/oracle.py verify
python3 tools/fts5/oracle.py metadata
```

Другая сборка может быть выбрана через `--sqlite /path/to/sqlite3`. Обновление
эталона — явное изменение манифеста после просмотра различий; обычная генерация
не меняет манифест. `metadata` печатает сведения, но ничего не перезаписывает.

Корпус использует упорядоченные поля и документы с внешними строковыми ID.
SQL rowid существует только в эталоне и отображается обратно в эти ID. Строки
передаются как SQL-значения через UTF-8 hex literals; MATCH не вставляется как
SQL-выражение. Имена колонок экранируются отдельно. Нескалярные JSON-значения,
числа, bool, null и отсутствующие поля при сравнении проецируются в NULL:
docid индексирует только строки и не воспроизводит SQL-приведение типов.

Критерий совместимости — одинаковые наборы ID и успешность/ошибка выражения.
Текст ошибок и неопределённый порядок SQLite не сравниваются. Фикстуры также
содержат токены, поля и позиции, полученные через fts5vocab(instance).

Воспроизведение и проверка:

```sh
python3 tools/fts5/oracle.py generate --output /tmp/docid-fts5-expected.json
cmp testdata/fts5/expected.json /tmp/docid-fts5-expected.json
go test ./...
```

Обычные Go-тесты читают сохранённые JSON-фикстуры и не требуют установленного
SQLite, Python, CGO или сетевого доступа. SQLite используется только отдельной
командой генерации и дифференциальной проверки.

## Таблицы unicode61

Публичный исходник SQLite с оригинальным уведомлением сохранён в
`tools/fts5/sqlite/fts5_unicode2.c`. Ссылка на закреплённую ревизию, SHA-256 и
версия Unicode находятся в соседнем `manifest.json`. Таблицы Unicode 6.1
воспроизводятся без сети:

```sh
python3 tools/fts5/unicode_tables.py
go test -run 'TestUnicode61|TestTextTokenizer' .
```

Преобразователь проверяет SHA-256 и извлекает только таблицы; алгоритмы работают
на Go. Текущие таблицы `unicode` из Go и нормализация NFKC не подменяют правила
SQLite. Настройки `remove_diacritics` 0/1/2, `categories`, `tokenchars` и
`separators` применяются одинаково к документу и запросу. Режим 1 сохраняет
исторические исключения SQLite, режим 2 удаляет также сложную диакритику.
Корпус проверяет совместимость сохранённого снимка с закреплённым CLI.

## Разбор MATCH

Лексер и парсер строят неизменяемое дерево, не привязанное к базе. Приоритеты:
неявный AND, бинарный NOT, явный AND, OR. Неявное соединение разрешено между
фразами и NEAR, но не рядом с выражением в скобках. `^` относится к началу
поля; `*` после строки — оператор префикса, внутри кавычек — содержимое строки.
Фильтры полей могут быть одиночными, групповыми, исключающими и вложенными.

Привязка имён полей выполняется отдельно от синтаксиса. Токенизация фраз
зависит от выбранного индекса и тоже выполняется после разбора. Поэтому
переиспользуемое дерево не содержит старых результатов поиска или ссылок на
изменяемый индекс. Принятые и отвергнутые выражения сравниваются с эталоном.

## Позиционные индексы в памяти

Каждое вхождение слова хранит токен, номер поля, внешний ID и позицию в B-tree.
Позиции независимы для каждого поля. Фразы и NEAR не пересекают границы полей.
Префиксы читаются диапазоном упорядоченного словаря; широкие префиксы могут
потребовать обхода большого числа вхождений. Транзакция использует copy-on-write
дерево; его изменения не влияют на опубликованное состояние до фиксации.

Память растёт с числом вхождений, а не только уникальных слов. Для оценки:

```sh
go test -run '^$' -bench '^BenchmarkTextPostings' -benchmem -benchtime=1x .
```
