# docid

Встраиваемая документо-ориентированная база данных для Go 1.24.3+.

- [Pebble](https://pkg.go.dev/github.com/cockroachdb/pebble@v1.1.5) хранит документы и определения индексов на диске.
- [google/btree](https://pkg.go.dev/github.com/google/btree@v1.1.2) используется для вторичных индексов в памяти.
- Документы — обычные JSON-объекты, объединённые в коллекции.
- Go DSL поддерживает фильтры, INNER/LEFT JOIN, сортировку и пагинацию.

## Подключение

Нужен Go 1.24.3 или новее. Модуль библиотеки — `github.com/totoer/docid`.

В каталоге вашего Go-модуля выполните:

```sh
go get github.com/totoer/docid
```

Для нового приложения сначала создайте модуль:

```sh
mkdir docid-demo
cd docid-demo
go mod init example.com/docid-demo
go get github.com/totoer/docid
```

## Быстрый старт

Создайте `main.go` в каталоге приложения:

```go
package main

import (
    "context"
    "fmt"
    "log"

    "github.com/totoer/docid"
)

type User struct {
    ID   string `json:"id"`
    Name string `json:"name"`
    Age  int    `json:"age"`
}

func main() {
    if err := run(); err != nil {
        log.Fatal(err)
    }
}

func run() (err error) {
    db, err := docid.Open("./data")
    if err != nil {
        return err
    }
    defer func() {
        if closeErr := db.Close(); err == nil {
            err = closeErr
        }
    }()

    users, err := db.Collection("users")
    if err != nil {
        return err
    }
    if err := users.Put("u1", User{ID: "u1", Name: "Анна", Age: 28}); err != nil {
        return err
    }

    var user User
    if err := users.GetInto("u1", &user); err != nil {
        return err
    }
    fmt.Println("Пользователь:", user.Name)

    var adults []User
    if err := users.Find().As("u").
        Where(docid.F("u.age").Gte(18)).
        OrderBy(docid.Asc(docid.F("u.name"))).
        SelectInto(context.Background(), "u", &adults); err != nil {
        return err
    }
    fmt.Println("Совершеннолетних:", len(adults))
    return nil
}
```

Запустите приложение:

```sh
go run .
```

В новом каталоге базы приложение выведет:

```text
Пользователь: Анна
Совершеннолетних: 1
```

Каталог `./data` создаётся относительно рабочей директории и сохраняется между запусками. Пример использует `Put`, поэтому повторный запуск заменяет документ `u1` и даёт тот же результат. Для создания документа с проверкой отсутствия ключа используйте `Insert`.

Пример с JOIN находится в [example_test.go](example_test.go); из каталога библиотеки его можно выполнить командой `go test -run '^Example$' -v .`.

Остальные примеры — фрагменты функций, возвращающих `error`. Они предполагают открытый `db`, заранее полученные коллекции (`users`, `orders`, `payments`) и необходимые импорты: `github.com/totoer/docid`, `context`, `encoding/json`, `errors`, `fmt`.

## Документы и коллекции

```go
err := users.Insert("u2", docid.Document{
    "id": "u2",
    "name": "Борис",
    "age": 32,
    "address": map[string]any{"city": "Белград"},
})
if err != nil {
    return err
}

user, err := users.Get("u2")
if err != nil {
    return err
}
fmt.Println(user["name"])
```

`Insert` принимает структуры с JSON-тегами, карты и `json.RawMessage`. Массив, примитив и `null` на верхнем уровне отклоняются с `ErrInvalidDocument`. Числа при чтении представлены `json.Number`, чтобы сохранять точность больших целых и десятичных значений.

ID — отдельный непустой строковый ключ в UTF-8 внутри коллекции. Он не добавляется в JSON автоматически. Если ID нужен в условии JOIN, сохраните его также как обычное поле документа, например `id`.

| Метод | Поведение |
| --- | --- |
| `db.Collection(name)` | Возвращает коллекцию, создавая её при необходимости |
| `db.Collections()` | Возвращает имена коллекций в лексикографическом порядке |
| `users.Insert(id, value)` | Создаёт документ; при занятом ключе возвращает `ErrAlreadyExists` |
| `users.Put(id, value)` | Создаёт документ или целиком заменяет существующий |
| `users.Get(id)` | Возвращает `Document`; при неизвестном ключе — `ErrNotFound` |
| `users.Delete(id)` | Удаляет документ; при неизвестном ключе — `ErrNotFound` |

Имена коллекций и индексов должны быть непустыми строками в UTF-8 без пробелов по краям. Некорректное имя или ID при записи возвращает `ErrInvalidName`.

Изменение карты, полученной через `Get` или запрос, не изменяет сохранённый документ: для записи используйте `Put`. Частичного обновления полей нет.

## Чтение в пользовательские структуры

`GetInto(id, &value)` читает документ непосредственно в пользовательский тип:

```go
type User struct {
    ID   string `json:"id"`
    Name string `json:"name"`
    Age  int    `json:"age"`
}

var user User
if err := users.GetInto("u1", &user); err != nil {
    return err
}

var adults []User
if err := users.Find().As("u").
    Where(docid.F("u.age").Gte(18)).
    OrderBy(docid.Asc(docid.F("u.name"))).
    SelectInto(context.Background(), "u", &adults); err != nil {
    return err
}
```

`SelectInto(ctx, alias, &slice)` извлекает документы выбранного псевдонима в `[]User` или `[]*User`. Условия, JOIN, сортировка и пагинация применяются как при `All`. JOIN может повторять один документ в нескольких элементах. Неизвестный псевдоним возвращает `ErrInvalidQuery`, даже если результат пуст.

`AllInto(ctx, &slice)` сохраняет структуру строк `All`: поля элемента соответствуют псевдонимам запроса. Например, для JOIN:

```go
type Order struct {
    Total int `json:"total"`
}
var rows []struct {
    User  User   `json:"u"`
    Order *Order `json:"o"`
}
err = db.From("users").As("u").
    LeftJoin("orders", "o", docid.F("u.id").EqField(docid.F("o.user_id"))).
    AllInto(context.Background(), &rows)
```

При отсутствии совпадения LEFT JOIN поле `Order` будет `nil`. Аналогично `SelectInto(ctx, "o", &orders)` возвращает `nil` для соответствующего элемента `[]*Order`; в `[]Order` получится нулевое значение.

Декодирование следует правилам `encoding/json`: поддерживаются JSON-теги, вложенные структуры, указатели и `json.Unmarshaler` (в том числе `time.Time`); неизвестные поля игнорируются. Числа в полях `any` остаются `json.Number`, а в типизированных полях проверяются тип и диапазон. ID из ключа коллекции автоматически не добавляется.

`SelectInto` и `AllInto` декодируют сохранённый JSON документов, как `GetInto`, без повторной сериализации карт `Document`. Пользовательские JSON-декодеры получают исходное представление документа; канонический порядок полей не гарантируется. Для запроса без условий, JOIN и сортировки промежуточные карты документов не создаются. Данные для декодирования копируются из согласованного снимка запроса; пользовательские декодеры вызываются после освобождения блокировки базы.

Передавайте ненулевой указатель; для методов запроса — указатель на срез. Некорректный приёмник возвращает `ErrInvalidDestination`. При успехе значение полностью заменяется, отсутствующие поля обнуляются, пустой результат запроса даёт пустой срез, отличный от `nil`. При ошибке приёмник не изменяется. Ошибки JSON-декодирования доступны через `errors.As`, например как `*json.UnmarshalTypeError`; ошибки хранения и запроса сохраняют прежние значения для `errors.Is`.

## DSL поиска

DSL встроен в Go. Поле задаётся через `F("alias.path.to.field")`. Без `As` имя коллекции служит псевдонимом.

```go
rows, err := db.From("users").As("u").
    Where(docid.And(
        docid.F("u.age").Gte(18),
        docid.F("u.address.city").In("Белград", "Нови-Сад"),
        docid.Not(docid.F("u.deleted_at").Exists()),
    )).
    OrderBy(docid.Desc(docid.F("u.age")), docid.Asc(docid.F("u.name"))).
    Offset(20).
    Limit(10).
    All(context.Background())
```

`users.Find()` эквивалентно `db.From("users")`. Результат — `[]Row`, где `Row` имеет тип `map[string]Document`: например, `rows[0]["u"]["name"]`.

| Выражение | Действие |
| --- | --- |
| `F("u.age").Eq(18)` / `.Ne(18)` | Равенство / неравенство |
| `.Gt(18)` / `.Gte(18)` / `.Lt(18)` / `.Lte(18)` | Сравнение |
| `F("u.city").In("A", "B")` | Принадлежность набору |
| `F("u.id").EqField(F("o.user_id"))` | Равенство полей |
| `F("u.name").Exists()` | Наличие поля, включая явный null |
| `F("u.name").IsNull()` | Только явный null |
| `And(a, b)` / `Or(a, b)` / `Not(a)` | Логические операции |

Повторные `Where` объединяются через AND. `And()` истинен, `Or()` и `In()` без аргументов ложны. Builder неизменяем: от одного запроса можно создавать независимые варианты и выполнять их параллельно.

Сравниваются скалярные JSON-значения. Числа сравниваются точно: `1`, `1.0` и `1e0` равны, а `9007199254740993` отличается от `9007199254740992`. Большие показатели степени сравниваются без разворачивания числа в память. Между разными типами `Eq` и упорядоченные сравнения ложны, `Ne` истинен. Массивы и объекты не участвуют в сравнениях; сравнение с отсутствующим полем всегда ложно, включая `Ne`. `Not` инвертирует булев результат, поэтому `Not(F("u.x").Eq(1))` также включает документы без `x`.

Сортировка по возрастанию: отсутствующее поле или нескалярное значение, затем `null`, `bool`, число, строка. Строки сравниваются по байтам UTF-8. При равенстве сохраняется исходный порядок по ID документов и ID присоединённых документов. Без `OrderBy` используется этот же порядок. `Limit(0)` возвращает пустой результат; без `Limit` ограничения нет.

Отрицательные `Limit`/`Offset`, неизвестные псевдонимы и некорректные выражения возвращают `ErrInvalidQuery` при выполнении. Неизвестная коллекция возвращает `ErrCollectionNotFound`; запрос сам коллекции не создаёт. Ошибки можно проверять через `errors.Is`.

Пути с точкой адресуют вложенные объекты; экранирование ключей с точками и адресация элементов массивов не поддерживаются. Псевдоним не должен содержать точку. Для коллекции с точкой в имени задайте псевдоним через `As`.

## JOIN

```go
rows, err := db.From("users").As("u").
    InnerJoin("orders", "o",
        docid.F("u.id").EqField(docid.F("o.user_id")),
    ).
    LeftJoin("payments", "p",
        docid.F("o.id").EqField(docid.F("p.order_id")),
    ).
    Where(docid.F("o.total").Gt(1000)).
    OrderBy(docid.Desc(docid.F("o.total"))).
    All(context.Background())
```

INNER JOIN возвращает совпавшие пары. LEFT JOIN сохраняет исходную строку при отсутствии совпадений; в таком случае `row["p"] == nil`. Связь «один ко многим» создаёт отдельную строку на каждое совпадение. Возможны цепочки JOIN и соединение коллекции с собой под разными псевдонимами.

`ON` принимает произвольное выражение DSL и может ссылаться на текущий и ранее объявленные псевдонимы. Например, `And(EqField(...), F("o.total").Gt(1000))`. Условия `ON` проверяются во время соединения, а `Where` — после всех соединений. Фильтр по присоединённому полю в `Where` может исключить строки LEFT JOIN без совпадения. Явные `null` равны друг другу; отсутствующие поля друг другу не равны.

Для равенства полей JOIN использует индекс присоединяемой коллекции, если он есть, в том числе для равенства внутри AND. В остальных случаях выполняется вложенный перебор.

## Индексы

```go
if err := users.CreateIndex(docid.Index{
    Name: "unique_email",
    Field: "email",
    Unique: true,
}); err != nil {
    return err
}
// Для ускорения JOIN по orders.user_id:
if err := orders.CreateIndex(docid.Index{Name: "by_user", Field: "user_id"}); err != nil {
    return err
}
```

Индексы создаются по существующим документам и автоматически обновляются при `Insert`, `Put`, `Delete`. `Indexes()` возвращает определения, `DropIndex(name)` удаляет индекс. Нарушение уникальности возвращает `ErrUniqueConstraint` и не изменяет документ. Неудачное создание уникального индекса не сохраняет его определение.

### Инициализация при повторном запуске

Определения индексов сохраняются на диске. Повторный `CreateIndex` с тем же именем возвращает `ErrAlreadyExists`, даже если определение совпадает. При старте приложения используйте проверку определения, чтобы заметить изменение поля или требования уникальности:

```go
func ensureIndex(collection *docid.Collection, want docid.Index) error {
    err := collection.CreateIndex(want)
    if !errors.Is(err, docid.ErrAlreadyExists) {
        return err
    }
    indexes, err := collection.Indexes()
    if err != nil {
        return err
    }
    for _, actual := range indexes {
        if actual.Name == want.Name {
            if actual != want {
                return fmt.Errorf("индекс %q: сохранено %+v, требуется %+v", want.Name, actual, want)
            }
            return nil
        }
    }
    return fmt.Errorf("индекс %q отсутствует после ErrAlreadyExists", want.Name)
}
```

Вызовите эту функцию после получения коллекции, до запуска обработки запросов:

```go
if err := ensureIndex(users, docid.Index{
    Name: "unique_email",
    Field: "email",
    Unique: true,
}); err != nil {
    return err
}
```

Для изменения определения удалите старый индекс через `DropIndex` и создайте новый. Эти операции выполняются отдельно; создание уникального индекса может завершиться ошибкой, если существующие документы нарушают уникальность.

### Использование индексов

Индексы разреженные: отсутствующее поле, массив или объект пропускаются. Явный `null` индексируется и участвует в уникальности. Индекс покрывает одно поле, включая вложенное. Оптимизатор использует индекс для `Eq`, `Gt`, `Gte`, `Lt`, `Lte` исходной коллекции и выбирает подходящее условие внутри AND. OR, NOT и IN проверяются перебором. Полное условие всегда проверяется после получения кандидатов.

## Обработка ошибок

Проверяйте ошибки через `errors.Is`, поскольку они могут содержать дополнительный контекст:

```go
user, err := users.Get("u1")
if errors.Is(err, docid.ErrNotFound) {
    return fmt.Errorf("пользователь u1 отсутствует: %w", err)
}
if err != nil {
    return err
}
fmt.Println(user["name"])

if err := users.Put("u2", docid.Document{"email": "anna@example.com"}); err != nil {
    if errors.Is(err, docid.ErrUniqueConstraint) {
        return fmt.Errorf("email уже занят: %w", err)
    }
    return err
}
```

Проверка уникальности в примере предполагает созданный уникальный индекс по `email`.

| Ошибка | Причина |
| --- | --- |
| `ErrNotFound` | Документ или удаляемый индекс не найден |
| `ErrAlreadyExists` | Ключ документа при `Insert` или имя индекса при `CreateIndex` уже заняты |
| `ErrUniqueConstraint` | Запись документа или создание индекса нарушает уникальность |
| `ErrCollectionNotFound` | В запросе указана несуществующая коллекция |
| `ErrInvalidDocument` | Значение не сериализуется в корректный JSON-объект |
| `ErrInvalidName` | Некорректное имя коллекции, определение индекса или ID при записи |
| `ErrInvalidQuery` | Некорректное выражение, псевдоним, пагинация или `nil` вместо контекста |
| `ErrInvalidDestination` | Некорректный приёмник для `GetInto`, `SelectInto` или `AllInto` |
| `ErrClosed` | Операция с закрытой базой |

Операции также могут возвращать ошибки хранилища, JSON-декодирования и отмены контекста. Для типизированных ошибок JSON используйте `errors.As`.

## Хранение и конкурентность

Документ сохраняется в Pebble как непосредственно сериализованный JSON-объект, без оболочки и служебных полей. Коллекции, ID и определения индексов имеют отдельные ключи. Имена кодируются для изоляции пространств ключей. Каждая запись использует `pebble.Sync`. Определения индексов сохраняются; B-деревья восстанавливаются из документов при `Open`.

Один `DB` безопасен для нескольких goroutine. Запись эксклюзивна; чтения могут выполняться параллельно. Запрос удерживает блокировку чтения на всё выполнение и видит согласованное состояние всех участвующих коллекций. `Close` ждёт текущие операции, повторный вызов успешен; дальнейшие операции возвращают `ErrClosed`. Каталог открывается одним процессом благодаря блокировке Pebble.

## Ограничения

- Индексы целиком размещаются в RAM; запуск с индексами требует чтения документов.
- Запрос материализует промежуточные строки и результат в памяти. Внутренние строки содержат ссылки на документы; JOIN копирует строку только при совпадении, а `All` создаёт карты только для итоговой страницы. Значения сортировки нормализуются один раз на строку.
- Отмена `context.Context` проверяется во время чтения и обработки строк, но ожидание блокировки, отдельный обход B-tree и сортировка не прерываются немедленно.
- Пользовательских транзакций, частичных обновлений, агрегаций и строкового SQL-парсера нет.
- Карты документов могут разделяться между строками одного результата; при независимом изменении строк скопируйте соответствующий документ, включая изменяемые вложенные карты и срезы.

## Бенчмарки

Быстрая проверка всех сценариев:

```sh
go test -run '^$' -bench . -benchtime=1x ./...
```

Для замера выбранной группы, например фильтрации:

```sh
go test -run '^$' -bench '^BenchmarkQueryFilter$' -benchmem -count=10 ./...
```

Один проход проверяет работоспособность и не подходит для выводов о скорости. Основная серия использует Pebble с файловой системой в памяти; запись на диск измеряется отдельно в `BenchmarkCollectionDurable`.

Список групп, методика и команды сравнения результатов — в [руководстве по бенчмаркам](docs/benchmarks.md).
